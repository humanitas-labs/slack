# ISS-0001 — Publish prebuilt binaries and a no-Cargo installer

GitHub: [#1 — Publish prebuilt binaries and a no-Cargo installer](https://github.com/digimata/slack/issues/1)

## Problem

The README currently installs with `cargo install --path .`. That requires users to clone the repository and install a Rust toolchain before they can use `slack`.

An operator should be able to install a versioned binary on a clean machine without Rust, Cargo, or a repository checkout.

## Decision

Make GitHub Releases the canonical binary distribution channel. Publish checksummed archives and provide a small installer that detects the host platform, verifies the checksum, and installs `slack` without requiring elevated privileges.

Keep `cargo install --path .` as a developer/source-build path, not the primary installation instruction.

## Scope

- Add release builds for:
  - `aarch64-apple-darwin`
  - `x86_64-apple-darwin`
  - `x86_64-unknown-linux-musl`
- Package each binary in a versioned `.tar.gz` archive with the README and license.
- Publish `SHA256SUMS` with every GitHub Release.
- Add a release workflow triggered by version tags.
- Require the tag, `Cargo.toml`, and `Cargo.lock` package versions to agree.
- Run format, Clippy, tests, release build, and `slack --version` before publishing.
- Provide an installer with this interface:

  ```sh
  curl -fsSL https://raw.githubusercontent.com/digimata/slack/master/install.sh | sh
  ```

- Detect OS and architecture; fail clearly on unsupported hosts.
- Download from the matching GitHub Release and verify SHA-256 before installation.
- Install to `${SLACK_INSTALL_DIR:-$HOME/.local/bin}` without `sudo`.
- Accept a pinned version through `SLACK_VERSION`.
- Download to a temporary file and replace an existing binary only after verification succeeds.
- Update the README so the binary installer is first and the Cargo path appears under development.

## Out of scope

- Automatic background updates.
- Package-manager repositories or taps. Homebrew can be a follow-up after the release artifacts are stable.
- Windows in the first release.
- Code signing and notarization in the first release; document the macOS quarantine behavior if it applies.

## Acceptance criteria

- On clean supported macOS and Linux hosts with no Rust installation, the documented command installs `slack` successfully.
- `slack --version` reports the release version after installation.
- The installer verifies the published checksum and refuses a corrupt or mismatched artifact.
- A failed download or verification does not overwrite an existing installation.
- The release workflow cannot publish when crate, lockfile, and tag versions differ.
- The README contains one primary installation command and a separate source-build section.
- The release workflow and installer have automated tests for platform selection, unsupported platforms, checksum failure, and custom install directories.
